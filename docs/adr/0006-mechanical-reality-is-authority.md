# 同一契约的四份表述：机械现实是权威，其余表述跟随并被钉住

状态：**定案**——2026-09-23 工具与提示词设计全量审查（grill-with-docs）定案。本文记录裁决原则；逐项修复以 issue 跟踪，落地随各票 PR。

## 背景

"阶段 X 能否在路径 P 上调用工具 Y"这类契约在仓库里有四份表述：

1. **声明式能力表**（`agents/runtime/capabilities.py`）——自称唯一权威；
2. **工厂实际挂载面**（`agents/runtime/factory.py` + 各阶段 adapter 传入的 `tools`）；
3. **中间件运行时拦截**（`stage_discipline.py` 及状态文案、executor 状态文本）；
4. **提示词/技能文案**（`agents/context/prompts/`、`skills/`、工具 description）。

2026-09-23 审查（main 044c7f8，逐条核验）发现多处漂移，其中三类直接产生行为伤害：

- **状态文案否定已存在的恢复路径**：环境失败首报文案教模型"缺包不可中途修，结束回合"（`core/test_executor.py:720-722`），而同一 executor 已实现 install-and-revalidate 周期（`:560-584`）、提示词也教模型用 `install_dependencies`（`test_driven_developer.py:29`）。
- **绝对化禁令吞掉合法例外**：工具策略一刀切禁读 `.arc`（`common.py:111`），但运行时为 `.arc/tdd_runs/**` 建了只读例外（`factory.py:566-568`），且 run_tests 结果明确要求模型读该处的持久化原始输出（`test_executor.py:455`）。
- **"无规则即允许"的表单元不反映真实挂载面**：能力表对 `(interface_design, run_build/run_tests)` 无规则即允许，但工厂从不给 DESIGN 挂载验证工具——表的裁决与挂载面脱节。

## 定案

**机械现实是唯一权威；能力表、状态文案、提示词是对它的表述，表述层漂移的修复方向永远是"表述跟随机械现实"，而不是让机械现实去迁就文案。**

具体含义：

1. **能力表是机械现实的声明层**，不是机械现实本身。表必须显式覆盖每个阶段的真实挂载面（含显式禁用），"无规则即允许"只能用于确实开放的默认面；最终 agent 的实际工具集合必须有钉子测试对着真实挂载面验证（能力表↔挂载面↔提示词三方互证，不只两张表互证）。
2. **状态文案只陈述真实存在的出口**。executor/中间件的拒绝与状态文本必须指向当前真实可用的恢复路径；路径尚未实现时不得预先描述，路径已实现时不得描述为不可用。
3. **提示词表述例外时必须完整**。凡运行时存在确定性例外的禁令（如 `.arc/tdd_runs` 只读），提示词必须同句表达例外，否则例外等于不存在。
4. **工具 description 是提示词的一部分**，与系统提示词受同一约束（#161 的 file_append 反例即工具描述滞后的案例）。

## 否决的替代

- **以提示词为权威、让运行时追赶文案**：文案无法被测试钉住，机械行为可以被。以不可测的一侧为权威会让漂移成为常态而非异常。
- **每处漂移各自裁决方向**：无统一原则时，"改文案还是改行为"会在每张票里重新争论一遍；本 ADR 预先给出方向，票只决定改哪一层。

## 后果

- 修复漂移的票据（第一批 A1/A2/A5 等）按"表述跟随"执行：改文案/能力表补显式裁决 + 钉子测试，不改变已正确的机械行为。
- 反向案例（机械行为本身错了，如混合退出码判定 `_tool_result_failed`）不在本 ADR 范围——那是实现缺陷票，修复的是机械现实本身。
- 新增工具/阶段/例外时，验收标准必须包含四层对齐检查：能力表、挂载面、拦截文案、提示词/工具描述。
